# Agent instructions — interactive-videos

- **Product authority:** `docs/DECISION-ATLAS.md` is the canonical record of owner-selected behavior and open product Questions. Treat Decisions as intent, not evidence that functionality is implemented. Preserve IDs and question/supersession history. Record new owner answers through the reviewable `/steer` workflow, one question at a time.
- **Architecture:** This repository owns video projects, their semantic `VideoSpec`, format packs, player integration and historical content. Reuse existing project catalog and Remotion pipeline. Reuse generic primitives from `remotion-primitives`; do not create a second animation engine. Shared asset generation/cache is owned by `asset-tooling`. Respect the content-addressed asset direction in `docs/adr/0001-videospec-v2-content-addressed-assets.md` without assuming issue #16 is already implemented.
- **Browser versus render:** Browser-only hover, focus, popovers and dialogs live at the interactive Player boundary; deterministic headless video frames must remain seekable and renderable without UI event histories, DOM measurements or network calls.
- **Acceptance:** For viewer-facing work, prove the actual project in the Pages app with Playwright exercising pointer and keyboard actions, not only component tests. Include visual/browser evidence when practicable. The Pages workflow publishes after merge; do not assert deployment before checking it.
- **Verification:** Use `bun run verify` (types, tests, render smoke, build and Playwright budget checks). Preserve the existing latency explainer and its interaction tests.
- **Execution:** GitHub issues track bounded implementation and acceptance, not product authority. The documentation-only steering PR is not an implementation authorization. Do not merge product-intent changes automatically.
